# V3.5 — 공백무시 평가 이후의 전체 성능업 재정의

작성일: 2026-08-20  
범위: KDoc 3축 전체 성능(Header/Footer · Long Text · Table)  
중요: **티처 재라벨링은 하지 않는다.**

## 0. 결론

> **확정 배합은 §9 다** — 무엇을 넣고 왜 넣었는지 한곳에 모아 두었다.
> 진행 요약: 조립 `body_fill` 로 학습 0 에 본문 62.93 → **74.74** · 3축 67.44 → **71.29**
> (849쪽 재추론 검증, §4.5.3). 남은 격차는 **표**이고, V3.5 배합은
> 표 증류 +22,556 · 한국어 crop +160,000 · 레이아웃 정제/증량 +125,000 이다.

V3.5의 문제 정의는 표 단독 성능업이 아니다.

> Header/Footer를 보존하면서 Long Text와 Table을 동시에 올려 KDoc 3축 평균을 70점대로 올리는 것.

V3.4까지의 가장 큰 착오는 공식 strict 점수를 보고 "표 구조를 거의 못한다"고 너무 빨리 결론낸 것이다.
공백만 제거하고 나머지 채점 조건을 오피셜과 동일하게 유지하면 우리 모델의 위치가 크게 달라진다.

## 1. 새 기준 — 공백무시 오피셜 호환 평가

새 평가 스크립트:

- `tools/eval_kdoc_compact_score.py`

이 평가는 오피셜 KDoc scorer와 동일하게 동작하되, 문자열 비교 전에 모든 공백을 제거한다.

유지하는 것:

- Header/Footer 평가 방식
- Long Text 평가 방식
- Table 평가 방식
- cell / up / down / left / right 조건
- top_heading / left_heading 조건
- table 구조 path 조건
- 3축 평균 계산

바꾼 것:

- 문자열 비교 전 공백 제거

즉 이 평가는 `table_text_all_anywhere`처럼 구조를 풀어버린 정보 생존 평가가 아니다.
정확한 이름은 **공백무시 오피셜 호환 평가**다.

해석:

1. 공백을 OCR 오류로 보지 않으면 V3/V3.4t의 Table은 20점대가 아니라 40점대다.
2. **채택 체크포인트는 `final`이 아니라 `checkpoint-1500`이다.** 모든 축이 V3 < s1000 < s1500으로
   단조 증가하다 마지막 120스텝에서 꺾인다. eval loss는 계속 내려갔지만(0.1080이 최저) 벤치는
   s1500이 정점 — **eval loss 최저점 ≠ 벤치 최고점.**
3. s1500은 V3 대비 Table **+3.23p**, Long Text **+1.22p**, 3축 평균 **+1.11p**다.
   **V3.1~V3.4 중 표와 본문이 처음으로 동시에 오른 버전이다.**
4. Table 45.66은 olmOCR(44.9)을 처음 넘었고 DeepSeek(46.6)까지 **0.9p** 남았다.
   §11.1의 "표만 최하위" 상태는 끝났다 — **이제 최하위 축은 Long Text(64.15)다**(BizOnAI와 −13.75p).
5. 유일한 회귀는 Header/Footer −1.14p(792건 중 9건)인데 스텝 비례 단조 하락이라 우연이 아니다.
   티처 데이터에 머리말/꼬리말이 없어 잊는 것으로 본다 → §5-C replay로 회복.
6. 그래도 PaddleOCR-VL 평균 70.2에는 아직 −1.65p 부족하다.

## 3. 공백 문제 재정의

공백 문제는 두 가지로 나눈다.

| 항목 | 판정 |
|---|---|
| 원천 HTML에서 원래 공백 복원 | 불가능. `<br>`/개행/시각적 간격 정보가 없으면 복원 근거가 없다 |
| 학습용 공백 정규화 | 가능하지만 보조책이다. 복원이 아니라 규약 통일이다 |
| 티처 재라벨링으로 이미지 기반 공백 재생성 | 가능하지만 **하지 않는다** |

따라서 V3.5에서는 티처 재라벨링을 하지 않는다.

남는 전략은:

1. 평가는 strict와 공백무시를 둘 다 보고한다.
2. 공백 정규화 학습셋은 실험 후보로만 둔다.
3. 원천 HTML 복원이라고 표현하지 않는다.
4. 불완전 생성된 normalized 파일은 학습 금지다.

현재 주의 파일:

- `data/pierrotocr/aihub_tables_norm/train.jsonl` — 중간에 끊긴 partial 파일. 학습 금지.
- `data/pierrotocr/aihub_tables_norm/val.jsonl` — 500건 완료. 단, 복원 GT가 아니라 정규화 GT.

한국어 정상 띄어쓰기까지 붙일 수 있다. 따라서 `aihub_tables_norm_v35` 는 **즉시 전량 투입 금지**,

### 4.5.2 왜 버리는가

`--mode hybrid-page` 가 쓰는 [merge_page_base](../../tools/hybrid_merge.py#L218)는
**page 통읽기 1회 결과를 최종 골격으로 삼고, c2f crop 중 `Table` 만 이식**한다.
`Text` `List-item` `Section-header` `Caption` `Footnote` `Title` crop은 **한 글자도 쓰이지 않는다.**

이 설계는 문서 파일 자체의 읽기순서를 지키려는 것이었으나, page 통읽기가 무너진 페이지에서는
잘 읽은 crop 결과까지 통째로 같이 버려진다.

실측 — `(대량) 경상북도_포항시_열린포항소식지 14`

| 항목 | 값 |
|---|---|
| 레이아웃 검출 | 52영역 (List-item 36 · Section-header 5 · Text 4 · Page-header 6 · Picture 1) |
| crop 인식 결과 | 51개 / **1,684자** — `개화시기 : 2024년 6월 ~ 7월`, `장소 : 남구 호미곶면 대보리 새천년광장 주변` 등 정확 |
| page 통읽기 | **333자에서 반복 루프로 붕괴** (`봉기산발기랑, 해양공업대, 족구공업,` 무한 반복) |
| 최종 md | **333자 = page 통읽기 그대로** |
| 채점 | text_present **0 / 127** |

이 한 페이지가 전체 본문 실패의 5.4%다. 같은 형태로 소식지·모집공고·편람 계열이 무너진다.

문서군별 본문 통과율 하위: 경상북도 13.1%(40/305) · 한국동서발전 35.6% · 국민건강보험공단 41.7% ·
교육부 44.3% · 한국인터넷진흥원 45.7% · 한국토지주택공사 46.6%.

실패의 66.8%가 **통과율 50% 미만 페이지 205쪽**에 몰려 있다. 고르게 틀리는 게 아니라 페이지 단위로 붕괴한다.

### 4.5.4 F안의 대가

F는 page 골격이 못 덮은 crop을 **뒤에 붙이는** 방식이라, 사람이 읽는 문서로서는 읽기순서가 흐트러진다.
md 평균 길이는 3,374 → 3,691자(×1.09)로 늘어난다. KDoc 3축은 위치를 채점하지 않으므로 점수 손해는 없지만,
**제품 산출물 품질은 F 이전이 낫다.** 따라서 F는 벤치 제출 경로로 두고, 제품 경로는
좌표 기반 병합(crop box와 page 블록을 y좌표로 정합)으로 따로 고친다.

## 6. 학습 방법

V3.5는 전면 재학습이 아니다.

| 항목 | 원칙 |
|---|---|
| 시작점 | V3 또는 V3.4t 중간 checkpoint. final 고정 아님 |
| step | 500 / 1000 / 1500 비교 |
| lr | 1e-6 ~ 3e-6 |
| 표 비중 | 30~35% |
| Long Text 비중 | 40% 이상 |
| Header/Footer/Layout/Text replay | 최소 20% |
| freeze | 가능하면 전체 파라미터보다 adapter/head/merger 우선 |
| 평가 | strict + 공백무시 오피셜 호환 둘 다 |

V3.4t final은 표 OCR 정보 생존을 올렸지만 본문을 깼다. 따라서 V3.5의 채택 기준은:

1. 공백무시 3축 평균 상승
2. strict 3축 평균 하락 없음 또는 제한적 하락
3. Header/Footer ≥ 96
4. Long Text 상승
5. Table 공백무시 상승

#### ① 표 — 티처 증류 (+22,556)

V3.4t 가 남긴 유일한 확실한 성과다. 50쪽 동일 표본·공백무시에서

| 축 | 티처(PaddleOCR-VL) | V3.4t | V3 |
|---|---:|---:|---:|
| 셀 읽기 | 94.0% | **71.9%** | 67.3% |
| 위치 | 86.0% | 79.8% | 81.9% |
| top_heading | 52.8% | **66.1%** | 69.1% |
| left_heading | 64.9% | 63.8% | 64.0% |

구조·헤더는 이미 티처보다 앞선다(top_heading +13.3p). **남은 격차는 셀 읽기 −22.1p 하나**이고
증류가 그 축만 올렸다. 그래서 증류분 17,556 을 전량 넣고, 구조 데이터는 더 넣지 않는다
(V3.3 이 구조를 550배 늘리고도 표 26.65 → 26.42 로 진 이유가 그것이다).

정규화본 5,000 은 **실험 물량**이다. 정규화는 복원이 아니라 규약 통일이고
`의 료 기 관 → 의료기관` 같은 삽입 공백 제거에는 맞지만 정상 띄어쓰기까지 붙일 수 있다(§3).

#### ② crop 인식 — 한국어 실문서 줄 증량 (+160,000)

body_fill 적용 후에도 남는 본문 실패 **1,589건** 중 근접 실패(0.85+)가 **588건**이고,
그 테스트의 **61.6% 가 `max_diffs` 0**(한 글자만 틀려도 탈락)이다. 틀리는 것은 구조가
아니라 **고유명사·기관명·전화번호의 한두 글자**다.

    산딸기랑 → 산발기랑 · 문명시민교육원 → 문명시민교육관
    휴직교원 → 휴식교원 · 419-4048 → 469-404 · 미술관 → 도서관

같은 도메인(한국어 공공문서 스캔)의 줄 crop 이 **7,078,061건 있는데 V3.0 은 80,000(1.1%)**
만 썼다. 3배로 올린다.

★ **길이로 뽑지 않는다.** 81~160자 구간은 243건뿐이고 그중 **50.6%**, >160자는 7건 중
**85.7%** 가 가로세로비 8 미만 — 여러 줄이 한 박스로 뭉쳐 어절 순서가 뒤섞인 불량 라벨이다
(Datasets.md §5.6). 무작위 증량이 정답이다.

☐ 미검증 — 71299 는 1990년대 문서이고 실패는 2024년 문서다. **글자 인식 정밀도가 도메인을
넘나든다**는 가정에 기대고 있다. 결과가 안 나오면 이 가정부터 의심한다.

#### ③ 레이아웃 — 정제 + 고밀도 (+125,000)

KDoc 849쪽에서 **블록 통째 누락이 37.5%**(단일 미덮 덩어리 ≥5%), 덮음률 <70% 인 쪽 11.2% 다.
원인은 모델이 아니라 **학습 라벨**이었다.

| 소스 | V3.0 | 요소/쪽 | **라벨 덮음률 중앙** | <70% 인 쪽 |
|---|---:|---:|---:|---:|
| `aihub_layout_ko` | 35,000 | 6.7 | **66.5%** | **52.7%** |
| `aihub_layout_ko_all` | 미사용 | 4.6 | 92.7% | 19.2% |
| `synth_ko_v2` layout | 40,000 | **21.3** | 100% | 0% |

V3.0 은 **"페이지의 3분의 1은 건너뛰어라"** 를 35,000건으로 가르쳤고 추론이 그대로 재현한다.
같은 원천에서 [gate_layout_coverage.py](../../tools/gate_layout_coverage.py) 로 덮음률 ≥90%
만 남겼다 — 221,035건 검사, **통과 100,000(45.4%)**, 검증 표본 2,000 에서 덮음률 중앙 **98.2%**,
90% 미만 **0건**.

밀도는 게이트로 못 올린다(통과분도 요소/쪽 4.8). 그래서 유일한 고밀도 소스
`synth_ko_v2` layout 을 40,000 → 100,000 으로 올린다. 합성이지만 **레이아웃 GT 는 배치
좌표라 오차가 없어** 인식과 달리 합성 편향 걱정이 적다.
